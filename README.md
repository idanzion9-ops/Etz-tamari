# עץ תמרי — אפליקציית המרחב

אפליקציית ווב (PWA) שאפשר להתקין על מסך הבית בטלפון. שני צדדים:

- **צד המבקר** — פתיח, סדנאות, חוגים, סדנאות פרטיות, פרויקטונים, חנות, הרשמה, האזור שלי.
- **מרכז הניהול** — נסתר לגמרי. אין אליו כפתור, אין אליו לשונית.

---

## פרויקטונים

מדור של עשרה רעיונות קטנים משאריות עץ. כל פרויקטון נפתח כמסך עבודה: רשימת חומרים, רשימת כלים, ושלבים שאפשר לסמן תוך כדי עבודה. ההתקדמות נשמרת על המכשיר — אפשר לעצור באמצע ולחזור מחר.

עורכים אותם בניהול ← פרויקטונים. שתי שדות דורשים פורמט מסוים:

- **חומרים** ו**כלים** — שורה לכל פריט.
- **שלבים** — שורה לכל שלב, בפורמט `כותרת | פירוט`. הקו האנכי הוא מה שמפריד בין הכותרת המודגשת לטקסט שמתחתיה.

---

## איך נכנסים לניהול

שלוש דרכים, כולן דורשות קוד:

1. **חמש לחיצות רצופות** על הלוגו למעלה.
2. **לחיצה ארוכה** (כשנייה) על השטח שמימין לשורה ״נבנה לזכרה של…״ בתחתית הדף.
3. הוספת `#admin` לכתובת.

הקוד ההתחלתי: **2580**. משנים אותו במרכז הניהול ← ״תוכן ומיתוג״ ← אבטחה.

> הקוד הוא מנעול נוחות, לא אבטחה. באתר סטטי כל קוד שנמצא בצד הלקוח ניתן לעקיפה על ידי מי שיודע לפתוח כלי פיתוח. הוא מספיק כדי שמבקר מזדמן לא ייתקל בניהול — הוא לא מספיק כדי להגן על מידע רגיש. אל תשמרו במערכת פרטים שאסור שיזלגו.

---

## איך תוכן חדש מגיע לכולם

זה החלק החשוב. האתר סטטי, בלי שרת. לכן:

1. במרכז הניהול עורכים סדנאות, חוגים, חנות, טקסטים ומועדים. **השינויים נשמרים על המכשיר שלכם** ומופיעים לכם מיד.
2. כשמוכנים: ניהול ← **פרסום וגיבוי** ← ״הורדת content.json״.
3. מעלים את הקובץ ל-GitHub, לתיקייה `assets/data/`, **במקום** הקובץ הקיים.
4. תוך דקה־שתיים כל מי שנכנס לאפליקציה רואה את התוכן החדש.

קובץ הפרסום כולל תוכן ציבורי בלבד: פתיח, אודות, שעות, סדנאות, חוגים, חנות ומועדים.
הרשמות, כספים, משתתפים ומשימות **לא נכללים בו** ולא מגיעים לאינטרנט.

לגיבוי של הכל (כולל הפנימי) יש כפתור נפרד. שמרו אותו אצלכם, אל תעלו אותו ל-GitHub.

בלי שרת, בקשה שמבקר שולח לא יכולה להגיע למכשיר שלכם לבד. לכן הזרימה היא:

מבקר ממלא את אשף ההרשמה → הבקשה נשמרת אצלו ב״האזור שלי״ → נפתחת אצלו הודעת וואטסאפ מוכנה עם כל הפרטים → הוא שולח לכם → אתם רושמים אותה בניהול ← ״הרשמות״.

**כדי שזה יעבוד חייבים למלא מספר וואטסאפ** בניהול ← תוכן ומיתוג ← יצירת קשר.
הפורמט: `972501234567` (קידומת מדינה, בלי אפס מוביל, בלי מקפים).

זה עובד מצוין להתחלה. כשהנפח יגדל, ראו ״השלב הבא״ בהמשך.

## העלאה ל-GitHub

הריפו: `idanzion9-ops/Etz-tamari`

**קבצים להחליף:** `index.html`, `manifest.webmanifest`, `sw.js`
**תיקייה להוסיף:** `assets/` (על כל תוכנה)
**קבצים להשאיר:** `icon-192.png`, `icon-512.png`
**קובץ למחוק:** `Etz_Tamari` — שריד לא בשימוש

מהדפדפן:
1. נכנסים לריפו ← `Add file` ← `Upload files`.
2. גוררים לתוך החלון את `index.html`, `manifest.webmanifest`, `sw.js` ואת **תיקיית** `assets` כולה. גרירת תיקייה שומרת על המבנה הפנימי.
3. `Commit changes`.
4. את `Etz_Tamari` מוחקים בנפרד: נכנסים אליו ← תפריט שלוש הנקודות ← `Delete file`.

### הפעלת הפרסום האוטומטי

יש עכשיו workflow בריפו, ולכן ההגדרה שונה מקודם:

`Settings` ← `Pages` ← תחת **Source** בוחרים **GitHub Actions** (לא ״Deploy from a branch״).

אחרי זה:

- כל `git push` ל-`main` מפרסם לבד.
- בלשונית `Actions` ← ״פרסום האפליקציה״ יש כפתור **Run workflow** להרצה ידנית.

ה-workflow בודק לפני הפרסום שקובץ התוכן תקין ושכל קבצי ה-JavaScript נטענים. אם משהו שבור — הפרסום נעצר והאתר הקיים נשאר באוויר.

הכתובת: `https://idanzion9-ops.github.io/Etz-tamari/`

> אחרי כל העלאה כדאי לרענן בכפייה (בטלפון: לסגור את האפליקציה ולפתוח מחדש). ה-Service Worker מוגדר לטעון את התוכן תמיד מהרשת, אבל את שאר הקבצים הוא שומר במטמון.

מה שתקבלו: עריכה מהטלפון שמופיעה מיד לכולם, הרשמות שנוחתות אצלכם בלי וואטסאפ, ומקומות פנויים שמתעדכנים לבד.

## אריזה כ-APK

יש שני workflows בריפו, והם עושים דברים שונים:

| Workflow | מתי רץ | מה הוא עושה |
|---|---|---|
| **פרסום האפליקציה** | בכל push, וגם ידנית | מפרסם את האתר. **זה מה שמעדכן את האפליקציה אצל המשתמשים.** |
| **בניית APK** | ידנית בלבד | בונה קובץ APK חדש להתקנה |

### למה APK חדש כמעט אף פעם לא נדרש

ה-APK לא מכיל את האפליקציה. הוא מעטפת שטוענת את האתר מהרשת. לכן:

| מה השתנה | מתי זה מגיע למשתמש |
|---|---|
| תוכן (`content.json`) | בפתיחה הבאה |
| קוד, עיצוב, מסכים חדשים | בפתיחה הבאה, או מיד אם האפליקציה ברקע |
| שם האפליקציה, אייקון, כתובת | רק עם APK חדש |

ה-Service Worker בודק עדכונים בכל פתיחה, בכל חזרה מהרקע ובכל חיבור מחדש לרשת. כשיש גרסה חדשה והמשתמש לא באמצע משהו, המסך נטען מחדש בשקט. אם מסך עבודה פתוח, מופיעה שורה ״גרסה חדשה מוכנה — הקישו לרענון״.

### הכנה חד-פעמית: מפתח החתימה

כל גרסאות ה-APK חייבות להיחתם באותו מפתח, אחרת אנדרואיד מסרב להתקין עדכון על גבי התקנה קיימת.

**1.** בטרמוקס, התקנת כלי החתימה:

```bash
pkg install -y openjdk-17
```

**2.** יצירת המפתח. בחרו סיסמה אחת וזכרו אותה:

```bash
cd ~
keytool -genkeypair -v -keystore android.keystore -alias etztamari -keyalg RSA -keysize 2048 -validity 10000
```

**3.** המרה לטקסט להדבקה:

```bash
base64 -w0 ~/android.keystore > ~/keystore.txt
```

```bash
cat ~/keystore.txt
```

**4.** בגיטהאב: `Settings` ← `Secrets and variables` ← `Actions` ← `New repository secret`. יוצרים שלושה:

| שם הסוד | הערך |
|---|---|
| `ANDROID_KEYSTORE_BASE64` | כל הטקסט הארוך מהפקודה הקודמת |
| `ANDROID_KEYSTORE_PASSWORD` | הסיסמה שבחרתם |
| `ANDROID_KEY_PASSWORD` | אותה סיסמה |

**5.** גיבוי. העתיקו את `~/android.keystore` ואת הסיסמה למקום בטוח מחוץ לטלפון.

> אובדן המפתח הוא בלתי הפיך. בלעדיו אי אפשר להוציא עדכון ל-APK — כל לקוח יצטרך להסיר את האפליקציה ולהתקין מחדש.

הקובץ לא נכנס לריפו: `.gitignore` חוסם אותו, וה-workflow משחזר אותו מהסוד בזמן הבנייה.

### בניית APK

`Actions` ← **בניית APK** ← `Run workflow`. ממלאים מספר גרסה (למשל `1.0.1`) ומריצים.

בסיום, בתחתית דף ההרצה, יש חבילה להורדה עם:

- `etz-tamari.apk` — להתקנה ישירה בטלפון
- `etz-tamari.aab` — להעלאה לחנות, כשתגיעו לשם
- `assetlinks.json` — לשלב הבא

מספר הגרסה הפנימי נלקח ממספר ההרצה של Actions, כך שהוא תמיד עולה ואנדרואיד תמיד מזהה את ה-APK כעדכון.

### הסרת שורת הכתובת

ה-APK נבנה כ-TWA. בלי אימות בעלות, אנדרואיד מציג שורת כתובת למעלה והאפליקציה נראית כמו דפדפן. האימות לא דורש דומיין בתשלום — רק ריפו נוסף:

1. יוצרים ריפו ציבורי חדש בשם **`idanzion9-ops.github.io`** בדיוק. השם הזה הוא מה שהופך אותו לאתר השורש.
2. מעלים אליו את `assetlinks.json` מהחבילה, לנתיב `.well-known/assetlinks.json`.
3. מפעילים בו Pages.
4. בודקים שהקובץ נטען: `https://idanzion9-ops.github.io/.well-known/assetlinks.json`
5. מתקינים מחדש את ה-APK. שורת הכתובת תיעלם.
